# CooK hardware architecture, layer by layer

> **Status: COMPLETE** (2026-11-20). Matches the RTL as of this date: GATEWAY = 1 board top, 2x2 mesh, multi-link fault codes, SW[7] program view.

The whole hardware architecture, layer by layer, from the board down to a single flit. Every part is simple on its own; the complexity comes from each layer adding its own protection against faults.

## 1. The layers

```
nexys4ddr_top  (board: clock, reset, switches, LEDs, 7-seg, DDR2 pins)
 ├─ MMCM 100→50 MHz, reset_sync, switch sync, fault_pattern()
 ├─ status_panel + seven_seg          (only OBSERVES status)
 ├─ cook_gw block design              (AXI DMA + SmartConnect + MIG → DDR2)
 └─ mesh_top                          (the 4 tiles)
     ├─ tile 0..2: picorv32 core + ni.v (RAM + CSRs)
     ├─ tile 3:    gw_ni.v (no core, no RAM; bridges to the AXI DMA)
     └─ noc_mesh                      (the network fabric)
         ├─ 4 × noc_router            (storage-free 5-port crossbar)
         ├─ 4 × bist_node             (between each router and its links)
         ├─ 8 × link_buffer           (FIFOs on the wires: 4 links × 2 directions)
         └─ 8 × end_buff              (dummy neighbours on mesh-edge ports)
```

```
 tile0 (0,0) ──── tile1 (1,0)
    │                 │            id = y*2 + x
 tile2 (0,1) ──── tile3 (1,1) = gateway → DMA → DDR2
```

## 2. What travels: packets and flits

- **Transaction size:** every transaction is a 2-flit packet: HEAD, then TAIL.
- **Flit layout:** 44 bits wide: `[chk 5 | poison 1 | type 2 | src 2 | dst_y 1 | dst_x 1 | data 32]`.
- **HEAD data:** `{class, tag, length-1, wstrb, is_resp, is_write, offset}`.
- **TAIL data:** the write data, or the read data in a response.
- **Destination:** absolute (x, y). Routers never modify a flit, so the parity bits generated by the sending NI are checked end to end.
- **Poison:** a router that has to cut a packet short sends a TAIL with the poison bit set and data `0xDEADBEEF`. That is the same `DEADBEEF` the restart demo read back from its timed-out polls.

## 3. Router and buffering

The router holds no flits. All storage is in the link FIFOs.

**`link_buffer`**
- A 6-slot FIFO on each one-way link (max packet 4 flits + 2 slack). It works as the downstream router's input buffer, but sits on the wire. This style is called elastic-buffer flow control.
- `in_ready` comes from a register: it depends only on how full the FIFO is. The earlier version computed it combinationally, which created a loop around the ring.
- `in_room` means "a whole maximum-size packet fits". This is what makes whole-packet admission work.
- It is also where the fault switches act: silent (the link never accepts) or bit-flip (data bit 0 inverted, so the parity breaks).

**Inside `noc_router`, in the order a packet meets them:**

1. **Route:** X first, then Y (X-Y routing). This is deadlock-free without virtual channels.
   - If BIST found dead links (2×2 mesh only), the packet goes around the ring 0-1-3-2-0 in whichever direction crosses no dead link.
   - If both directions are blocked, the packet is dropped with E_ROUTE. This is the cut-off case in the multi-link tests.
2. **Admission:** a HEAD may leave only when the next FIFO has room for a whole packet (`out_room`).
3. **Wormhole lock:** the output stays locked to that packet until its TAIL passes, so packets can't interleave. A round-robin pointer picks between inputs.
4. **Checks on every incoming flit:**

   | Condition | Action | Flag |
   |---|---|---|
   | Bad parity on an idle input | drop the flit | E_CHK |
   | BODY or TAIL with no route held (orphan) | drop | E_ORPHAN |
   | HEAD to a missing, disabled or dead port | drop | E_ROUTE |
   | Bad parity mid-packet, or the source changes mid-packet | replace with a poison TAIL | E_CHK / E_PROTO |
   | A new HEAD inside a packet (lost TAIL) | send a poison TAIL to close the old packet, keep the new HEAD | E_PROTO |

5. **Watchdog per output** (one tick = 4 cycles):
   - **Output locked with no progress for 8 ticks:** if the downstream FIFO is ready, the upstream lost the rest of the packet, so the router sends a poison TAIL. If the downstream is stuck, the output is marked dead.
   - **A HEAD waiting 64 ticks without being admitted:** the output is marked dead.

**Why the buffering looks complex:** whole-packet admission means that in a healthy network, a locked output never stalls. A stall therefore always means a fault, never congestion. That one property lets the watchdog tell "broken" from "busy", and most of the router logic exists to keep it true.

## 4. BIST: what happens after every reset

All four `bist_node`s run the same fixed schedule in lockstep while the cores are held in reset:

| Step | What happens | Result |
|---|---|---|
| 1. Ping-pong, in the order E, S, W, N | Each router sends alternating all-0 and all-1 words on that output. The neighbour checks them and sends one pong back. | in and out bits per port |
| 2. Local echo | A ping on the L port is reflected back by a register | the L bits |
| 3. Router self-test | Every input→output path gets a 2-flit packet, plus a 2-inputs-to-L arbitration test | `rt_status`; any failure = code F, all links of that router dead |
| 4. Gossip | 4 rounds: each router shares its dead-link mask over verified links only | the same `dead_links` in every router |
| 5. Gateway check | `gw_ni` reads every tile's BIST CSR `0x014` over the network. The value must equal its own complement. | `avail[]` bitmap |
| 6. Start | `sys_ready` rises, the cores leave reset, and the DMA lock opens | LED13 on |

- Every status bit starts as "faulty" and only a passed test sets it. A missing answer can never read as healthy.
- **Known limitation:** a broken in-link also fails the out-link, because the pong can't get back. That's why one directional switch code kills the whole physical link, at both ends.
- On the board, the whole sequence also waits for DDR2 calibration first (`sys_rst_n`).

## 5. Network interface (`ni.v`): one per core tile

**Core side:** picorv32 → address decoder → local (RAM or CSR) or remote (packet).

**Remote reads**
- Timeout of 1024 cycles, then a resend with a new tag, up to 2 retries. That makes 3 attempts, about 61 µs at 50 MHz. This matches the 12.2 s measured on the board: 200,000 polls × 61 µs.
- After the last retry, the core receives `0xDEADBEEF` and the timeout flag is set. The core never hangs.
- A response whose tag doesn't match the current attempt (a late or stale one) is discarded and flagged.
- **Remote writes are posted:** there is no reply, so a lost write is not detected. Software must read back to confirm.

**Response queue:** an incoming read request moves out of the receive register at once. This avoids a request/response deadlock between two tiles.

**RAM:** one true-dual-port BRAM. Port A belongs to the core, port B to the network. It is preloaded from `.mem` files.

**Protection windows**
- **Writes:** other tiles may write only the mailbox, `0x800–0xEFF`. The gateway may write anywhere from `0x100` up, because DMA lands there.
- **Reads (`RD_PROTECT=1`):** other tiles may read only the CSRs and the mailbox. Anything else returns poison.

**CSR map (each tile, offset in its region):**

| Offset | Register |
|---|---|
| `0x000` | tile ID |
| `0x004` | error flags, write 1 to clear: [0] timeout, [1] illegal address, [2] poison received, [3] stale response, [4] parity |
| `0x008` | software status: `600D` / `FA11` / `5255`. This is what SW7 shows. |
| `0x00C` | number of tiles |
| `0x010` | kind: 0 = core tile, 1 = gateway |
| `0x014` | BIST status {in, out}, plus the same 10 bits inverted |
| `0x018` | core control: read bit 0 = trapped; write 1 = restart |
| `0x100+` | RAM (C programs: reset stub at `0x100`, mailbox `0x800–0xEFF`, code from `0x1000`) |

## 6. Gateway (`gw_ni.v`): tile 3

Same packet rules as `ni.v`. It has three jobs:
1. Pass core accesses at `0x200–0x2FF` through to the AXI DMA registers (AXI4-Lite).
2. **MM2S** (DDR → tile): each streamed word becomes a posted write into a tile's RAM.
3. **S2MM** (tile → DDR): read N words from a tile and stream them to the DMA.

| Offset | Register |
|---|---|
| `0x100`–`0x110` | MM2S destination, S2MM source / count, status, word counter |
| `0x114` | DMA lock: read = claim (queued round-robin); write = release; lease timeout |
| `0x118` | reject reason (1–9): no lock, DDR zone, tile range, alignment, …, BIST not done |
| `0x120` | `sys_ready` + availability bitmap |
| `0x130+4t` | stored BIST status of tile t |

- **Checks before a transfer starts:** the requester owns the lock, its tile is available, the transfer stays inside its own tile, and it stays inside its own DDR zone.
- **DDR zones:** three private 40 MB zones (tiles 0, 1, 2) plus two shared 4 MB windows.

## 7. Board layer

- **Fault injection:**
  - SW12 + SW[3:0] picks a link fault through `fault_pattern()`, which drives the `link_buffer`s.
  - SW11 picks silent or bit-flip.
  - SW10 + SW[9:8] breaks a router's self-test.
- **`status_panel`:** reads only. It picks the highest-priority error on the lowest tile and drives the display, the blink codes and the LEDs. SW7 bypasses it to show a tile's status register.

## 8. Which layer catches which fault

| Fault | Caught by | Reaction |
|---|---|---|
| Broken link, present at reset | BIST ping-pong + gossip | Route around it on the ring (code E) |
| Broken router, present at reset | BIST self-test | The tile is cut off (code F) |
| Corrupted flit | Parity check at the router or NI | Drop or poison (code 3 / 8) |
| Lost packet or response | NI timeout + retry | `DEADBEEF` + timeout flag (code 2) |
| Stuck output | Router watchdog | Poison TAIL or dead port (code 6 / 7) |
| Bad address or window | Address decoder, NI windows | Poison / dropped (code A) |
| DMA misuse | Gateway checks + lock | Refused, with a reason (code C / D) |
| Core crash | Trap bit in `0x018` | Another core can restart it (code 1) |
